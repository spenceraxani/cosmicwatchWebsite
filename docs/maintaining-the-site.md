# Maintaining the CosmicWatch website

What updates by itself, what needs an edit, and where each edit goes. Every
file below can be edited on GitHub in the browser (open the file, click the
pencil); the site rebuilds after the change is committed.

## Updates by itself

| What                                                 | Where it comes from                                                                                                                     |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Guide pages (`/docs/guides/…`)                       | The four PDFs in the v3X repository, regenerated by the daily sync (`.github/workflows/sync-guides.yml`, 09:17 UTC) when a PDF changed. |
| Parts List and Digi-Key order lists                  | `Purchasing_List_v3X_sa.xlsx` in the v3X repository, regenerated by the same daily sync (`scripts/sync-bom.py`).                        |
| Firmware version, file names, recent commits         | The same daily sync (`scripts/github-snapshot.mjs`); the Downloads page also asks GitHub live.                                          |
| "Open the PDF" links (`/pdf/…`)                      | Load the newest PDF straight from GitHub.                                                                                               |
| Firmware download (Downloads page)                   | The newest `.uf2` file in the repository's `Firmware/` folder, checked in the visitor's browser.                                        |
| "Download the GUI" (home page and Downloads page)    | Zips the repository's `GUI/` folder in the visitor's browser, straight from GitHub (`src/assets/scripts/guiDownload.ts`).               |
| Gerbers, purchasing list, placement sheet, enclosure | Links to the files on GitHub; their current names come from the snapshot, so a new Gerber version is picked up.                         |

The site keeps no copies of these files, so there is only one set to maintain:
the v3X repository.

## Guide pages from the PDFs

`scripts/sync-guides.py` reads each PDF's bookmarks and turns each chapter into
a page; figures, tables and equations become images in `public/guides/`.

- To update a guide, update the PDF in the v3X repository. The next daily run
  (or **Actions → Sync guides from the v3X repository → Run workflow**)
  regenerates the pages, formats them and commits them.
- A "Fig. ??" or "Sec. ??" on a guide page is in the PDF itself (an unresolved
  LaTeX reference). Fix it in the LaTeX source and re-upload the PDF.
- To run it by hand: `pip install pymupdf pillow`, clone the v3X repository,
  then `python3 scripts/sync-guides.py --repo <path to the clone>` and
  `pnpm exec prettier --write src/content/docs/docs/guides src/data_files/guides.json`.

## Example measurements on the home page

The six cards under **What You Can Measure** are chosen by hand in
`src/data_files/measurements.ts`. They do not change when the guides change.
Each entry is one card:

```ts
{
  url: '/docs/guides/example-measurements/tested-measurements/cosmic-ray-muon-velocity/',
  title: 'Measuring the Speed of Muons',
  summary: 'One or two sentences, ideally quoted from the guide.',
  image: m_velocity, // imported at the top of the file from src/images/cw/
  alt: 'What the image shows',
},
```

- **Add one:** copy an entry, point `url` at the guide page (open the page on
  the site and copy its path), add an image to `src/images/cw/` and import it
  at the top of the file.
- **Remove or reorder:** delete or move entries; the page shows them in order.
- The "See all 20 measurements" link goes to the full list in the guides, which
  does update by itself. If the number of measurements changes, update
  `home.measurements.all` in `src/copy/en.ts`.

## Parts list and Digi-Key order list

The table and the Digi-Key **Bulk Add** lists on `/docs/parts-list/` are
generated from `Purchasing_List_v3X_sa.xlsx` in the v3X repository by
`scripts/sync-bom.py` (daily, with the guides). **To change a part, edit the
xlsx on GitHub**; the website follows within a day (or run the sync workflow).

`src/data_files/bom-extras.json` holds what the xlsx does not: the Digi-Key
product page and the cut-tape order number (…CT-ND) where the xlsx lists a
tape-and-reel or Digi-Reel number, plus Digi-Key searches for parts bought
elsewhere. Each extra is tied to the xlsx part number it was written for; if
the xlsx changes that part, the extra is ignored and the xlsx's own number is
used, so a replaced part is never ordered under its old number.

`pnpm check:bom` compares the website's list with the xlsx on GitHub at any
time.
